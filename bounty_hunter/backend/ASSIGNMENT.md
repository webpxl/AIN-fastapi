# Assignment: Galactic Bounty Board API

## Context

The year is 2787. Across dozens of star systems, a network of independent contractors — bounty hunters — tracks and captures the galaxy's most wanted fugitives. To coordinate this work, the Galactic Authority runs a central **Bounty Board**: a live registry of active targets, their last-known locations (by planet and sector), and the reward offered for their capture.

You have been contracted to build the backend API that powers this board. The frontend interface has already been built by the design team and is ready and waiting — but without a working backend, it shows nothing.

## Getting Started

The full stack runs via Docker. Start everything with:

```bash
docker-compose up --build
```

Once running, open [http://localhost:4242](http://localhost:4242) in your browser. You'll see the Galactic Bounty Board interface — dark, atmospheric, and completely empty. Your job is to make it come alive.

The frontend talks to your API at `http://localhost:8000`. You can verify your API is running by visiting [http://localhost:8000](http://localhost:8000), which should return a confirmation message. Furthermore, you can inspect the endpoints using Swagger via [http://localhost:8000/docs](http://localhost:8000/docs).

## What You Need to Build

Your task is to implement the backend in four steps. Each builds on the previous.

---

### Step 1 — Database Setup (`database.py`)

This file is given to you — **no changes needed**.

It sets up three things:

- **`engine`** — the connection to the SQLite database file
- **`get_db`** — a generator function that opens a database session, yields it to whichever endpoint needs it, and closes it cleanly afterwards. You'll import and use this in `main.py`.

```python
from sqlalchemy import create_engine
from sqlalchemy.orm import Session

SQLALCHEMY_DATABASE_URL = "sqlite:///./galactic_bounty_board.db"

engine = create_engine(SQLALCHEMY_DATABASE_URL, connect_args={"check_same_thread": False})

def get_db():
    with Session(engine) as db:
        yield db
```

> `check_same_thread=False` is required when using SQLite with FastAPI, because FastAPI may handle a single request across multiple threads.

### Step 2 — Data Models (`models.py`)

Define two database tables using **SQLModel**. Each class inherits from `SQLModel` with `table=True`, which tells SQLModel to treat it as a real database table rather than just a schema.

**`Planet`** — a location in the galaxy

- `id`: optional integer, primary key (use `Field(default=None, primary_key=True)`)
- `name`: unique, indexed string
- `sector`: indexed string (e.g. `"Outer Rim"`, `"Mid Core"`)
- `bounties`: one-to-many `Relationship` to `Bounty`, with cascade delete

**`Bounty`** — a wanted individual

- `id`: optional integer, primary key
- `target_name`: indexed string
- `reward_amount`: integer, default `1000`
- `status`: string, default `"Active"` (either `"Active"` or `"Captured"`)
- `planet_id`: optional integer, foreign key to `"planets.id"`
- `planet`: `Relationship` back to `Planet`

> Because `id` is auto-generated by the database, it must be `Optional[int]` with `default=None` so you can create instances before they're inserted.
> Think carefully about which side of the relationship holds the foreign key, and how cascade deletes should work.

### Step 3 — Schemas (`schemas.py`) ✅ Provided

This file is given to you — **no changes needed**.

Pydantic schemas are separate from your ORM models — they define the exact shape of data coming in from HTTP requests and going out in HTTP responses. Study them before writing your endpoints: the schema names tell you what each endpoint expects and returns.

You can find the schema definitions in `schemas.py`.

> `from_attributes=True` tells Pydantic it can read data from ORM model attributes, not just plain dictionaries.

---

### Step 4 — API Endpoints (`main.py`)

Build a **FastAPI** application with the following endpoints. Import `engine` and `get_db` from `database.py`, make sure `get_db` is passed as a dependency to each endpoint so FastAPI automatically opens and closes a database session per request.

**General**
- `GET /` — health check, returns a welcome message

**Planets**
- `POST /planets` — create a planet (reject duplicate names with `409 Conflict`)
- `GET /planets` — list all planets, sorted by name
- `GET /planets/{planet_id}` — get one planet (`404` if not found)
- `PUT /planets/{planet_id}` — update a planet
- `DELETE /planets/{planet_id}` — delete a planet (and its bounties)

**Bounties**
- `POST /bounties` — create a bounty (validate the planet exists)
- `GET /bounties` — list all bounties, sorted by reward descending
- `GET /bounties/{bounty_id}` — get one bounty
- `PUT /bounties/{bounty_id}` — update a bounty
- `DELETE /bounties/{bounty_id}` — delete a bounty

**Reports**

- `GET /reports/sector-intel` — return a list of `SectorIntelGroup` objects, each with:
  - `sector`: the sector name
  - `bounties`: all bounties in that sector (full `BountyOut` objects, ordered by reward descending)

The **CORS** configuration is already present, so the frontend (on port 4242) should be able to reach your API.

---

### Step 5 — Seed the Database (`seed.py`)

Write a script that populates the database with sample data so you (and the frontend) have something to work with.

Add at least:
- **4 planets** spread across at least **2 sectors**
- **6 bounties** with a mix of `"Active"` and `"Captured"` statuses and varying reward amounts

Run it within the backend Docker container:

```bash
docker exec -it api python seed.py
```

We could also install the requirements for the backend locally and then adjust the DB file locally, but that's a bit ugly so [let's not](https://www.youtube.com/watch?v=LkvE1A8TrWM) do that.

Then refresh [http://localhost:4242](http://localhost:4242) — the board should now show your bounties, planets, and sector intel.

## Tips

- Build and test incrementally — get the database working before writing endpoints.
- Use the FastAPI interactive docs at [http://localhost:8000/docs](http://localhost:8000/docs) to test your endpoints without needing the frontend.
- The `docker-compose.yml` mounts your `backend/` folder into the container, so changes apply instantly (no rebuild needed).
- If you break the database, delete `galactic_bounty_board.db` and re-run `seed.py`.
